分析 emotion-diary 当日导出数据，输出结构化 AI 洞察。

**输出字段以 `src/shared/aiInsightManifest.ts` 为准**；下方 JSON 为当前 manifest v5 示例。  
**完整使用与修改说明**：项目根目录 `docs/AI使用与修改说明.md`。

## 步骤

0. **跨日上下文（推荐）**：读取 `%APPDATA%/emotion-diary/data/ai-results/` 目录下，目标日期**之前**最近 **3–5 个**已有 JSON（按 `date` 排序）。提取其中的 `mood_index`、`ability_growth_score`、`growth_phase_label`、`continuity_summary`、`key_insight` 等，用于步骤 ⑪ 的跨日连贯分析；若目录为空则跳过。
1. 确定日期：`$ARGUMENTS` 若为空则用今天（本地日期 YYYY-MM-DD）。
2. 读取导出文件（Windows 用户数据目录）：
   - `%APPDATA%/emotion-diary/data/ai-export/{date}.json`
   - 若文件不存在，提示用户先在「记录」页保存至少一条当日日记（保存后会自动写入 ai-export）。
3. 分析 `entries` 数组中每条记录：

   **文字内容读取规则（按优先级）：**
   - 优先读取 `reaction_note`；若为空则尝试 `fact`；若仍为空则尝试 `thought`
   - 若三个文字字段均为空，该条记录标记为「仅坐标」，只做象限位置分析，不做文字解读
   - 若多条记录的文字内容完全相同，注明「疑似重复录入」，在 `writing_feedback` 中提示

   **坐标轴语义：**
   - `coord_x`（X 轴）= 任务价值 / 重要性，-5（低价值）→ +5（高价值）
   - `coord_y`（Y 轴）= 耗能程度，-5（低耗能）→ +5（高耗能）
   - 四象限：心流区（+x, -y） / 攻坚区（+x, +y） / 机械区（-x, -y） / 内耗陷阱（-x, +y）

   **分析任务清单：**

   **① 认知扭曲识别** → 输出 `cognitive_distortions`
   只标记文字中**明确出现**的内容，不要推断或主观解读。逐类匹配以下触发特征：
   - **过度概括**：含「每次」「总是」「永远」「从不」「所有人都」等绝对化频率词
   - **灾难化**：含「完了」「毁了」「肯定失败」「一切都完蛋」「最糟糕」等极端预测
   - **非黑即白**：「要么…要么」「不是…就是」「如果不…就彻底」等非此即彼表达
   - **读心术**：「他们一定觉得」「他肯定认为我」「大家都看出来了」等臆测他人想法
   - **自我否定**：「我真没用」「我做什么都不行」「我不适合」「我太差了」等自我贬低
   - **应该化**：「我应该早就…」「我必须做到…」「不能接受自己这样」等带强烈义务感的内疚表达
   - **情绪化推理**：「我感觉很糟，所以这件事一定不行」等用情绪代替事实判断
   `quote` 字段直接引用原文，不超过 25 字；若同一条记录有多个扭曲，分别列出。

   **② 主题提炼** → 输出 `thought_themes`（≤5 条）
   - 用 **3-8 字名词短语**描述，如「产品功能规划」「与上级沟通压力」「对自我能力的质疑」
   - 只提炼在文字中**明确出现**的内容，不要推断；单次偶发提及不算主题
   - 若仅 1 条有效记录，直接从该记录中提炼 1-2 个最核心的关注点即可
   - 若多条记录文字相同（重复录入），视为 1 条处理，只提炼 1-2 个主题并在 `writing_feedback` 注明

   **③ 逐条速览** → 输出 `entry_summaries`（每条记录必须有一项）
   - 有文字：格式为「[触发事件/场景] + [情绪/状态]」，如「收到批评邮件，感到自我怀疑」「讨论产品改版方案，思维活跃」
   - 若该记录存在认知扭曲，摘要末尾加「· 含[扭曲类型]」，如「…· 含过度概括」
   - 坐标极端时（`|coord_y| ≥ 3`）体现强度，如「高度心流（专注投入）」或「强耗能内耗状态」
   - 仅坐标无文字：写「[象限名]，无文字」，如「内耗陷阱，无文字」
   - 全部记录写完，不要遗漏

   **④ 象限与时段分析** → 输出 `quadrant_stats` / `patterns`
   - 统计各象限出现次数 → `quadrant_stats`
   - 找出 `coord_y ≥ 2` 的记录，按 `occurred_at` 的小时归组，若集中在某时段则写入 `patterns`，如「下午 14-17 点耗能持续偏高」
   - 对比上午（6-12 时）/ 下午（12-18 时）/ 晚间（18-24 时）的象限分布；若三段分布差异明显，写入 `patterns`
   - 若多条记录按时间排序后 `coord_y` 持续上升，写入 `patterns`，如「记录耗能随时间递增」

   **⑤ 身心关联** → 补充进 `summary` 或 `patterns`（仅当 `body_tags` / `behavior_tags` 有数据时）
   - 若同一 `body_tag`（如「肩颈紧」「胸闷」）在多条记录中出现，写入 `patterns`，如「身体紧绷信号反复出现」
   - 若 `body_tags` 出现时对应 `quadrant` 均为内耗陷阱，写入 `patterns`，如「身体紧绷与内耗陷阱高度相关」
   - 三个字段均为空则跳过此项，不要捏造

   **⑥ 数据质量评估** → 输出 `data_quality`
   - `rich`：≥ 70% 的记录有 **50 字以上**有效文字，且内容各不相同
   - `moderate`：30%-70% 的记录有有效文字，或文字普遍较短（10-50 字）
   - `sparse`：< 30% 的记录有有效文字，或大多数记录文字重复
   `sparse` 时，`cognitive_distortions` 和 `thought_themes` 字段可能不可靠；在 `summary` 末尾加一句说明，如「因记录文字较少，以上分析仅供参考。」

   **⑦ 写作反馈** → 输出 `writing_feedback`（`data_quality` 为 `rich` 时省略此字段）
   按以下模板选择适用的反馈，语气友好，不批评：
   - 无文字记录：「记录 {id}（{时间}）只有坐标定位，建议补充：当时发生了什么？是什么让你有这种耗能感？」
   - 文字过短（< 20 字）：「记录 {id} 文字较简短，可以尝试多写一句：这件事为什么影响了你？」
   - 重复录入：「多条记录的文字完全相同，可能是误操作；若是有意记录，可以尝试每条写一个新角度」
   - 只有事件没有感受：「记录 {id} 描述了事件，但没有写内心感受，加一句『我当时感到…』会让分析更准确」

   **⑧ 风险等级评估** → 输出 `risk_level`
   依据以下信号叠加判断（满足越多越高）：
   - **强信号**（每项 +2）：连续 3 条以上落在内耗陷阱 / 出现灾难化或自我否定扭曲 / `body_tags` 含「胸闷」「心跳加速」「头痛」等躯体化信号
   - **弱信号**（每项 +1）：有 1-2 条内耗陷阱 / 出现绝对化表达 / 晚间 20 点后仍有 `coord_y ≥ 3` 的记录
   - 总分 ≥ 4 → `high`；1-3 → `medium`；0 → `low`
   - 若绝大多数记录无文字（`data_quality: sparse`），无法判断信号时默认 `low`，在 `risk_signals` 中注明「文字不足，风险无法准确评估」

   **⑨ 仪表指数（必填，0–100 整数）** → `ability_growth_score` / `experience_richness_score` / `mood_index`
   - **能力增长点**：心流区、攻坚区占比越高越高；`coord_x` 均值偏正加分；疲劳检查 `decision_quality` 高加分；内耗陷阱占比高则扣分。无记录时写 `0`。
   - **经历丰富点**：有效文字条数、`thought_themes` 多样性、日记平均字数、`entry_count` 综合；重复录入扣分。`sparse` 时通常 ≤40。
   - **心情指数**：`coord_x` 均值与内耗陷阱占比综合（内耗多、x 偏负则低）；心流区多、x 偏正则高。不要与 `risk_level` 混用同一套规则，但方向应一致。

   **⑩ 仪表结构化字段（v4+，必填）** — 输出情境-原因链，禁止空泛形容词：
   - `mood_trend`：`up` / `down` / `stable`，相对昨日同类记录或当日早晚变化
   - `mood_context`：≤40 字，一句说明今日心情指数背后的情境（如「下午内耗拉高，整体低于昨日」）
   - `risk_reason`：≤30 字，风险主因名词短语（如「连续决策过载」），用于 UI「中风险：xxx」
   - `growth_contributors`：≤3 条，能力增长点依据（如「上午心流写作」「攻坚任务完成」）
   - `experience_highlights`：≤3 条，经历丰富点依据；可与 `thought_themes` 重叠但更偏「今日高光瞬间」
   - `value_energy_tags`：≤6 条，价值/耗能高频标签（如「心流区·上午」「内耗陷阱·下午」），从象限+时段+patterns 提炼
   - `guidance_primary`：一条可执行的 5% 微迭代主行动（≤50 字），从 `recommendations` 中选最重要的一条单独写出
   - `guidance_target_time`：可选，如 `15:00`，仅当主行动含明确时间点时填写

   **⑪ 跨日连贯（v5，必填）** — 结合步骤 0 的历史 ai-results 与当日分析：
   - `growth_phase_label`：四选一 `筑底期` | `突破期` | `高原期` | `回落期`（相对近几日能力/心情走势）
   - `continuity_summary`：≤60 字一句，体现连续感（如「连续第 3 天下午内耗偏高，能力分仍缓升」），禁止孤立形容词

4. `risk_level` 已在 ⑧ 中通过信号叠加评估，此处直接采用结论。
5. 生成 `key_insight`（≤80 字，用于 App 提醒条）：
   - 优先提炼**最显著的一个发现**，按以下优先级选择角度：
     1. 存在认知扭曲 → 点出最高频的扭曲类型与原文片段，如「日记中反复出现『每次都这样』等过度概括」
     2. 有明确时段规律 → 点出耗能集中时段，如「下午 14-17 点连续落入内耗陷阱」
     3. 有清晰主题 → 点出今日最核心关注，如「今日思维集中在产品架构规划，整体心流状态良好」
     4. 数据不足 → 如「今日记录文字较少，坐标显示整体处于心流区，建议补充文字以获得更准确分析」
   - 不要堆砌多个结论，一句话聚焦一个点。
6. 写入结果文件：`%APPDATA%/emotion-diary/data/ai-results/{date}.json`
